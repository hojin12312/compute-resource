# 슬라이드 덱 사용법

**▶ [덱 열기](https://hojin12312.github.io/compute-resource/slides/)** — 101장. 내용은 [메인 README](../README.md)와 같고, 이쪽은 발표용 표현입니다.

브라우저만 있으면 됩니다. 설치할 것도, 인터넷도 필요 없습니다 — reveal.js도 폰트도 레포 안에
들어 있어 **외부에서 받아오는 것이 하나도 없습니다.** 어느 기기에서 열어도 같은 글자로 보입니다.

그림은 이미지가 아니라 **그 자리에서 렌더한 것**입니다(`figures/*.html`). 그래서 확대해도
글자가 벡터로 선명하고, 테마를 바꾸면 그림도 함께 바뀝니다.

---

## 넘기기

| 키 | 하는 일 |
|---|---|
| `→` · `Space` · `N` | 다음 장 |
| `←` · `P` · `Shift+Space` | 이전 장 |
| `Shift` + `←` / `→` | 맨 처음 / 맨 끝으로 |
| **숫자** | **장 번호로 바로 가기** — `3` `2` `Enter`면 32장. `Esc`로 취소 |
| `G` | 같은 기능을 여는 reveal 기본 키 (장 제목 검색도 됩니다) |
| `Esc` · `O` | 전체 슬라이드 한눈에 보기 |
| `F` | 전체화면 |
| `B` · `.` | 화면 잠깐 끄기 (검은 화면 — 질문 받을 때) |
| `S` | 발표자 노트 창 열기 |

## 발표 도구

| 키 | 하는 일 |
|---|---|
| `L` | **레이저 포인터** — 마우스를 따라 붉은 점이 움직입니다 |
| `D` | **필기** — 마우스로 끌어서 그립니다 |
| `E` | 지우개 — 지나간 획을 지웁니다 |
| `C` | 펜 색 바꾸기 (시안 → 앰버 → 보라 → 흰색) |
| `Z` / `Shift+Z` | 한 획 되돌리기 / 다시 |
| `X` | 이 장의 필기 전부 지우기 |
| `T` | **라이트 / 다크 테마** |

같은 키를 다시 누르면 꺼집니다. `Esc`는 도구를 먼저 끄고, 도구가 없을 때만 슬라이드 목록을 엽니다.

**마우스만 쓰실 때는 포인터를 화면 아래쪽으로 내리세요** — 도구막대가 올라옵니다.

알아두면 편한 것 세 가지:

- **필기는 장마다 따로 남습니다.** 넘어갔다 돌아오면 그대로 있습니다.
- **창 크기를 바꿔도 필기는 그림 위 같은 자리에 있습니다.** 발표 중에 화면이 바뀌어도 안 어긋납니다.
- **테마를 바꾸면 필기 색도 같이 바뀝니다.** 시안으로 표시한 것은 라이트에서도 시안입니다.

## 라이트 테마

`T`로 바꿉니다. 고른 테마는 기억되어 다음에 열 때 그대로 나옵니다.

**그림 56장도 함께 밝은 판으로 바뀝니다.** 밝은 회의실이나 프로젝터가 약할 때 쓰시면 됩니다.
색이 곧 의미인 자료라(앰버 = 비싼 것, 시안 = 아낀 것, 보라 = 더 세게 아낀 것, 회색 = 계산 안 함)
라이트에서도 그 뜻이 같게 읽히도록 색을 따로 맞췄습니다 — 대비비와 색약 기준을 계산해 정한
값입니다.

그림이 실시간 렌더링이라 **테마 전환에 이미지를 다시 받지 않습니다.** 그림 스스로 두 벌의
색을 갖고 있어 그 자리에서 바뀝니다.

## 발표자 노트

`S`를 누르면 별도 창이 열립니다. **모든 장에 노트가 들어 있고**, 본문에 넣지 않은 상세·수치 근거·검증 수준이 거기 있습니다. 화면에는 골자만 띄우고 말로 채우는 구성입니다.

노트 창은 인터넷 없이도 열립니다.

## 휴대폰 · 태블릿

- **화면을 탭하면** 가로 전체화면이 됩니다. 다시 탭하면 돌아옵니다.
- **좌우로 밀면** 넘어갑니다. 넘기려고 문지른 것은 탭으로 치지 않습니다.
- 세로로 들고 있으면 내용을 90도 돌려 화면을 채우고, **기기를 가로로 돌리면 회전이 자동으로 풀립니다.**
- 아이폰 사파리에는 전체화면 기능 자체가 없어서, API에 기대지 않고 화면을 채우는 방식으로 만들었습니다.

휴대폰에는 키보드가 없어 도구·테마 단축키는 쓸 수 없습니다. 테마는 마지막에 고른 값을 따릅니다.

## 화면 크기

슬라이드는 **1376 × 774 = 정확히 16:9**입니다. 16:9 화면(FHD 프로젝터 등)에서는 위아래 검은 띠가 **0px**입니다.

그림은 실시간 렌더링이라 **해상도 상한이 없습니다.** 4K·5K 화면에서도 글자가 벡터로 선명합니다.
(브라우저에서 파일을 직접 열었을 때는 캡처된 3840 × 2160 이미지가 쓰이는데, 그것도 FHD
프로젝터와 고해상도 화면 모두에서 뭉개지지 않는 크기입니다 — 아래 "오프라인" 참고.)

16:9가 아닌 화면에서는 남는 자리가 어두운 여백이 되고, 내용이 잘리거나 늘어나지는 않습니다.

## 그 외

- **PDF로 저장** — 주소 끝에 `?print-pdf`를 붙이고 브라우저 인쇄(여백 없음 · 배경 그래픽 켜기). 현장에서 브라우저가 말썽일 때의 대비책입니다.
- **오프라인** — 레포를 내려받아 `slides/index.html`을 그대로 열어도 됩니다. 서버가 필요 없습니다.
  이때는 브라우저가 `file://`에서 파일 목록을 읽지 못해 **그림이 캡처된 이미지로 대체됩니다**
  (101장·폰트·필기·테마는 그대로). 실시간 렌더링까지 그대로 보시려면 레포 루트에서
  `python3 -m http.server`를 띄우고 `localhost:8000/slides/`로 여세요.
- **그림이 안 뜨는 최악의 경우** — `slides/present.js` 첫머리의 `LIVE_FIGURES`를 `false`로
  두면 예전처럼 캡처된 이미지만 씁니다. 발표 직전 문제가 생기면 이 한 줄이 대비책입니다.
- **고친 게 안 보일 때** — **하드 리로드**하세요. Chrome·Edge는 `⌘⇧R`(윈도우 `Ctrl+F5`), Safari는 `⌥⌘E`로 캐시를 비우고 `⌘R`. GitHub Pages가 10분짜리 캐시를 내려주기 때문이고, 그냥 두어도 10분 뒤에는 풀립니다.
  주소 끝에 `?v=2`를 붙이는 것으로는 **해결되지 않습니다** — 그건 `index.html`만 새로 받게 할 뿐, 그 안에서 부르는 CSS·그림은 URL이 같아 여전히 캐시에서 나옵니다.
