# 부록 B · 어텐션 계보 문답 — `h`에서 MLA까지

[← 본문으로 돌아가기](../README.md#65-glm-52---indexshare와-비동기-강화학습)

본문 [6.5장](../README.md#65-glm-52---indexshare와-비동기-강화학습)은 MHA·GQA·MQA·MLA를 그림
한 장과 몇 문장으로 지납니다. 이 부록은 그 그림을 검수하는 과정에서 나온 문답을 순서대로 정리한
것입니다. **"왜 그렇게 되는가"를 수식 수준에서 따라가고 싶을 때** 읽으면 됩니다.

표기는 **[1차]**(논문·설정 파일에서 직접 확인), **[유도]**(이 문서의 계산), **[미확인]** 입니다.
수식 출처는 대부분 [DeepSeek-V2 논문](https://arxiv.org/abs/2405.04434)(MLA를 도입한 논문)이고,
절·식 번호는 그 논문의 것입니다.

## 1. `h`가 무엇인가

`h`는 **그 레이어의 어텐션 블록에 들어가는 입력 벡터**입니다. 논문 표기도 "attention input of
the t-th token at an attention layer"입니다. **[1차]**

```
토큰 id (정수)  ─[임베딩 테이블 조회]→  h⁰ (GLM-5.2는 6144차원)

레이어 ℓ:   h ─[norm]→ 어텐션 ─(+잔차)→ ─[norm]→ FFN/MoE ─(+잔차)→ h′
            ↑                                                        └→ 다음 레이어의 h
            └ 여기에 W^Q·W^K·W^V (또는 MLA의 W^DKV)를 곱합니다
```

- 토크나이저가 내놓는 것은 **정수 id**입니다. 벡터가 되려면 임베딩 테이블을 한 번 거칩니다.
- **첫 레이어의 `h`는 임베딩 조회 결과뿐**입니다. 둘째 레이어부터는 직전 레이어의 FFN(MoE
  모델이면 전문가 블록) 출력에 잔차를 더한 값입니다.
- 엄밀히 어텐션 투영이 받는 것은 `h` 자체가 아니라 **정규화를 통과한 `h`** 입니다(pre-norm).
  논문이 `W^Q h_t`로 적는 것은 정규화를 표기에서 생략한 것입니다.
- **`h`는 토큰마다, 그리고 레이어마다 따로 있습니다.** GLM-5.2는 78층이니 토큰 하나에 `h`가
  78개 있고, 레이어마다 자기 투영으로 자기 K/V(또는 잠재)를 만듭니다. 그래서 [4장의 KV캐시
  공식](../README.md#4-llm에게-일을-시키려면-얼마만큼의-메모리가-필요할까요)에 **레이어 수**가
  곱해집니다.
- 잔차 연결 때문에 `h`는 층을 지나며 덮어써지지 않고 **누적**됩니다(잔차 스트림). 40층의 `h`는
  그 토큰에 대해 모델이 그때까지 계산한 것을 다 담고 있습니다. [6.6장의 Attention
  Residuals](../README.md#66-kimi-k3---kimi-delta-attention-kda)와 [부록 A의 Hyper-Connections](./deepseek-v4.md#hyper-connections--잔차를-네-벌로-들고-섞습니다)가
  손대는 대상이 이 누적 방식입니다.

## 2. `h`에서 Q·K·V가 갈라진다 — 그리고 K와 V가 짝인 이유

같은 `h` 하나에서 세 갈래로 갈립니다. 헤드마다 자기 몫의 투영이 있습니다. **[1차]**

```
q_t = W^Q h_t      k_t = W^K h_t      v_t = W^V h_t

A의 헤드 출력 = Σ_B  softmax( q_A · k_B / √d ) · v_B
                        ↑ A에서            ↑ B에서   ↑ B에서
```

**자주 틀리는 지점: Value는 질문하는 토큰이 아니라 참조되는 토큰에서 나옵니다.**

- `q_A` = "A가 무엇을 찾는가"
- `k_B` = "B가 무엇으로 검색되는가"
- `v_B` = "B가 실제로 건네줄 내용"

A는 매칭 점수를 가중치로 삼아 **B들의 내용을 섞어** 받습니다. `v_A`도 쓰이지만 그것은 A가
자기 자신에게도 어텐션하기 때문이고(인과 마스크에서 A는 자신과 과거를 봅니다), "A의 값이라서"가
아닙니다.

**이 짝짓기가 KV캐시가 왜 K와 V인지를 설명합니다.** K와 V는 둘 다 **참조되는 쪽(과거 토큰)의
산물**이라 다음 스텝에도 계속 필요하니 저장합니다. Q는 **지금 물어보는 토큰**의 산물이라 그
스텝이 끝나면 버립니다. 캐시가 QK나 QV가 아닌 이유입니다.

그리고 이것이 MLA가 성립하는 조건입니다 — K와 V가 **같은 토큰의 `h`에서 나오기 때문에** 병목
하나를 공유해도 둘을 다 만들 수 있습니다.

## 3. MHA → GQA → MQA는 한 축 위의 세 점

셋을 따로 외울 필요가 없습니다. **KV 헤드 수 `n_g` 하나**가 축입니다. **[1차]**

```
n_g:   n_h ──────────────── 8 ──── 2 ──── 1
        │                          │      │
       MHA                        GQA    MQA
```

`n_g = n_h`면 MHA, `n_g = 1`이면 MQA, 그 사이가 GQA입니다.
[GQA 논문](https://arxiv.org/abs/2305.13245)이 이렇게 정의합니다. 실제 모델은 대개 `n_g = 8`
입니다 — Llama 2 70B가 Q 64 : KV 8, Llama 3 8B가 32 : 8.

**무엇이 줄고 무엇이 안 주는지**를 갈라 두는 것이 중요합니다.

| | MHA → GQA로 바꾸면 |
|---|---|
| KV캐시 | `n_g/n_h`로 줄어듭니다 (64:8이면 1/8) |
| KV 읽기 대역폭 | 같은 비율로 줄어듭니다 → 디코딩이 빨라집니다 |
| `W^K`·`W^V` 파라미터 | 출력 차원이 줄어 함께 작아집니다 |
| **어텐션 연산량** | **그대로입니다** |

마지막 줄이 오해되기 쉽습니다. Q 헤드가 그대로 `n_h`개니 점수 계산도 `n_h × 컨텍스트` 번
그대로 일어납니다. 공유된 K/V 헤드를 그룹 내 쿼리들에게 **복사해서 쓰는(broadcast)** 것이라
계산이 줄지 않습니다. **GQA가 사는 것은 저장과 읽기이지 연산이 아닙니다.**

**품질은 순서대로 떨어집니다.** DeepSeek-V2 논문 Appendix D.1의 7B 통제 실험(같은 구조,
어텐션만 교체, 파라미터를 7B로 정렬)에서 MMLU가 **MHA 45.2 · GQA(8그룹) 41.2 · MQA 37.9**
입니다. **[1차]**

**만드는 방법**: GQA는 처음부터 학습할 필요가 없습니다. MHA 체크포인트에서 그룹 안의 K/V
헤드를 평균으로 합친 뒤 원래 학습량의 5% 정도만 추가 학습하면 됩니다 — GQA 논문 제목의
"from Multi-Head Checkpoints"가 그 뜻입니다.

**8장과 이어지는 실무적 결과**: KV 헤드 수가 텐서 병렬의 상한이 됩니다. `n_g = 8`이면 KV를
8장까지 쪼개 나눌 수 있고 그 이상으로 TP를 키우면 KV를 **복제**해야 합니다. MQA·MLA는 KV가
실질적으로 한 벌이라 처음부터 복제이므로, "TP를 늘리면 KV캐시가 복제된다"는 말은 그 계열에만
해당합니다 — GQA 모델에 그대로 옮기면 틀립니다.

## 4. 그럼 MHA는 왜 `h`를 저장하지 않는가

`h`가 K+V보다 작다면 `h`만 저장하고 필요할 때 K/V를 만들면 될 것 같습니다. 실제로 그 발상은
성립하고, **MLA는 그 발상에 저랭크 병목을 더한 것**입니다. 하지만 고전 MHA에서는 손해입니다.

**첫째, 이득이 2배뿐입니다.** 고전 MHA는 관례가 `헤드 수 × 헤드 차원 = hidden_size`입니다 —
Llama 2 7B가 `32 × 128 = 4096`, 70B가 `64 × 128 = 8192`. 그러면 K와 V 각각이 `h`와 같은
크기이므로 **K+V는 `h`의 딱 2배**입니다. **[유도]**

> GLM-5.2에서 `h`(6144) 대 K/V(32,768)가 5.3배로 벌어지는 것은 헤드를 hidden보다 넓게
> 잡았기 때문이고(`64 × 256`), 그것은 **MLA가 캐시를 헤드 수에서 떼어낸 뒤에야 가능해진
> 선택**입니다. 순서가 반대입니다 — MLA가 있어서 헤드를 넓게 쓴 것입니다.

**둘째, 재계산이 폭발합니다.** `h`만 들고 있으면 매 스텝 과거 토큰 **전부**에 대해
`k_B = W^K h_B`, `v_B = W^V h_B`를 다시 계산해야 합니다. 컨텍스트 길이 × `d²` 규모의 연산이
레이어마다, 스텝마다 붙습니다.

**셋째, 흡수로 재계산을 피하면 이번엔 연산이 헤드 수배로 뜁니다.** [6장](#6-흡수--결합법칙을-쓰는-것)의
흡수를 쓰면 K/V를 만들지 않아도 되지만, 과거 토큰 하나당 내적 차원이 이렇게 됩니다. **[유도]**

| | 과거 토큰 하나당 내적 차원 |
|---|---|
| MHA, K/V 저장 | 헤드마다 **128** (자기 슬라이스만) |
| MHA, `h` 저장 + 흡수 | 헤드마다 **4096** (전체 폭) |
| MLA, 잠재 저장 + 흡수 | 헤드마다 **512** (공유 병목) |

MHA의 K/V는 **이미 헤드별로 잘려 있어서** 각 헤드가 128차원만 보면 됩니다. `h`를 저장하면 그
절단이 사라져 모든 헤드가 4096차원 전체와 내적해야 합니다 — 메모리 2배를 아끼려고 연산을
32배로 늘리는 거래입니다. MLA가 이 함정을 피하는 이유는 병목이 **처음부터 헤드 사이에 공유되도록
학습돼서** 512로 충분하기 때문입니다.

**넷째, RoPE가 흡수 경로를 막습니다.** 위치 회전이 `W^Q`와 `W^K` 사이에 끼면 접을 수 없습니다
(§2.1.3). 그래서 RoPE를 쓰는 현대 MHA에서 `h` 저장은 재계산 경로밖에 남지 않습니다. **[1차]**

**한 걸음 물러나면**: KV캐시는 설계 결정이 아니라 **메모이제이션**입니다. 학습과 프리필에서는
모든 토큰의 K/V를 한 번에 병렬로 계산하므로 캐시가 아예 필요 없습니다. 캐시는 디코딩에서
"이미 계산한 것을 또 계산하지 않기 위해" 생긴 것이고, 그렇다면 **어텐션이 추가 연산 없이 곧바로
쓸 수 있는 가장 좁은 값**을 남기는 게 자연스럽습니다. MHA에서 그것이 헤드별 K/V이고, MLA는
아키텍처를 바꿔 그 "가장 좁은 값"이 576개가 되게 만든 것입니다.

## 5. MLA — K/V 투영의 저랭크 공동 분해

### 무엇이 분해되는가

**K·V 벡터가 아니라 그것을 만드는 투영 행렬입니다.** **[1차]** (§2.1.2, 식 9\~11)

```
c_KV = W^DKV h          (식 9)   ← 입력은 h입니다. K도 V도 아닙니다
K    = W^UK  c_KV       (식 10)  ← 헤드 수로 잘라 헤드별 K가 됩니다
V    = W^UV  c_KV       (식 11)
```

실효 투영으로 보면 `W^K = W^UK·W^DKV`, `W^V = W^UV·W^DKV`입니다. 즉 **MHA의 K/V 투영을 랭크
512로 인수분해한 것**입니다. 그리고 다운프로젝션은 **한 벌만 있어 K와 V가 공유**합니다 — 논문
절 제목이 "low-rank key-value **joint** compression"인 이유입니다.

```
h ─[W^DKV]→ c_KV(512) ─┬─[W^UK]→ K (헤드별)
                       └─[W^UV]→ V (헤드별)
```

**파라미터는 셋(다운 1 + 업 2), 캐시는 하나(`c_KV`)** 입니다. 질문의 두 요소가 서로 다른 층에
있습니다 — "하나만 쓴다"는 저장의 성질이고 "저랭크로 분해한다"는 파라미터의 성질이며, 후자가
전자를 가능하게 합니다.

### 왜 헤드 수와 KV 크기가 분리되는가

`c_KV`는 헤드 수와 무관한 512차원입니다. 헤드 수가 늘어나도 커지는 것은 `W^UK`·`W^UV`(가중치,
사용자 수와 무관)이고 **캐시는 그대로**입니다. [부록 A](./deepseek-v4.md#8-flash와-pro-설정-비교)에서
V4 Pro가 헤드를 64 → 128로 늘렸는데도 KV캐시가 그대로인 것이 이 성질입니다.

### 오토인코더가 아니라 LoRA입니다

"계산된 K/V를 저차원으로 눌러 저장한 뒤 다시 펴는 것"으로 이해하면 두 군데가 틀립니다.

1. **압축의 입력이 K/V가 아니라 `h`입니다.** 전체 크기의 K/V를 만든 적이 없습니다. GLM-5.2에서
   `h`는 6,144차원이고 헤드 전부의 K/V는 32,768개인데, 다운프로젝션은 **6,144 → 512**이지
   32,768 → 512가 아닙니다.
2. **재구성 목표가 없습니다.** 오토인코더는 자기 입력을 복원하도록 학습되지만, `W^DKV`와
   `W^UK`는 언어모델 손실로 함께 학습됩니다. 복원해야 할 "원본 MHA의 K/V"가 애초에 존재하지
   않습니다. 그래서 논문이 MLA를 "조금 나쁘지만 싸다"가 아니라 **MHA보다 점수가 높다**고
   보고할 수 있습니다(Appendix D.2). **손실 압축이 아니라 다른 파라미터화**입니다.

비유로는 **LoRA**가 정확합니다 — 큰 행렬을 두 작은 행렬의 곱으로 대체하는 구조이고, 설정
필드명도 `kv_lora_rank`입니다. **[1차]**

### 크기는 두 축의 곱입니다 — 6.25%가 아니라 28.1%

여기서 가장 헷갈리는 대목입니다. "쌍이 하나가 되었으니 절반"이라고 생각하면 8헤드 토이에서
`1/16 = 6.25%`가 나와야 합니다. 그런데 실제 MLA는 그보다 큽니다 — **아낀 자리를 폭에 쓰기
때문입니다.** **[1차]** 논문 Table 1과 캡션이 그 설정을 밝힙니다: `d_c = 4·d_h`,
`d_h^R = d_h/2`이므로 토큰당 `4.5·d_h·l`, 그래서 *"GQA 2.25그룹과 같은 양인데 성능은 MHA보다
강하다."*

```
개수 축 :  쌍(2) → 하나(1)      ×1/2   →  8헤드 토이에서 6.25%
차원 축 :  d_h → 4.5·d_h        ×4.5   →                28.1%
```

**[유도]** 8헤드 토이(MHA = 16단위)로 네 방식을 같은 잣대에 놓으면 이렇습니다.

| | 단위 | MHA 대비 |
|---|---|---|
| MHA | 16 | 100% |
| GQA 2그룹 | 4 | 25% |
| **MQA** | 2 | **12.5%** |
| **MLA** | 4.5 | **28.1%** |

두 가지가 따라옵니다.

- **MLA는 MQA보다 작지 않습니다 — 항상 2.25배 큽니다.** MQA와 MLA는 둘 다 헤드 수와 무관하니
  이 배수는 헤드가 몇이든 같습니다. MLA가 사는 것은 **최소 바이트가 아니라 바이트당 품질**
  입니다(D.1: MQA의 MMLU 37.9 대 MHA 45.2).
- **그런데 실제로 배포되는 GQA는 8그룹입니다**(Llama 2 70B 64:8, Llama 3 8B 32:8). 캐시는 그룹
  수에 비례하니 같은 헤드 수에서 MLA(2.25그룹 등가)가 **약 3.6배 작으면서 품질은 MHA보다
  높습니다**(D.2). 이것이 프론티어 모델들이 MLA를 고르는 이유입니다.

퍼센트를 인용할 때는 **분모의 헤드 수를 반드시 밝혀야 합니다.** 8헤드에서 28.1%인 값이
R1의 128헤드에서는 1.4%가 되는데, 줄어든 이유는 MLA가 작아진 게 아니라 **MHA만 헤드 수에
비례해 커졌기** 때문입니다.

### 파라미터는 오히려 줄어듭니다

캐시가 커지는 것과 파라미터가 커지는 것은 방향이 반대입니다. **[유도]** R1 설정(`d` 7168,
헤드 128×128, `d_c` 512, `q_lora` 1536)으로 레이어당 어텐션 파라미터를 세면:

| 경로 | 같은 기하의 MHA | MLA | 비율 |
|---|---|---|---|
| K | 117.4M | 12.1M | **10.3%** |
| V | 117.4M | 12.1M | **10.3%** |
| Q | 117.4M | 48.8M | 41.5% |
| O | 117.4M | 117.4M | 100% |
| **합계** | **469.8M** | **187.1M** | **39.8%** |

MHA의 `W^K`는 `7168 × 16,384` 한 장인데 MLA는 `7168 × 512` + `512 × 16,384`로 쪼개집니다 —
병목이 훨씬 작으니 곱의 합이 원래 곱보다 작습니다. LoRA가 파라미터를 줄이는 것과 같은 산수
입니다. `d_c`를 128 → 512로 키우면 KV 경로가 5.1M → 20.4M이 되지만 MHA의 234.9M에는 여전히
10% 수준입니다.

**`d_c`를 키운 진짜 대가는 연산입니다.** 흡수한 형태에서 헤드마다 576차원 내적을 하므로 MHA의
192차원보다 약 2.7배입니다 — 대역폭을 사고 연산을 내주는 거래이고, [디코딩이 대역폭
병목](../README.md#52-디코딩)이라 남습니다. 참고로 61층을 합쳐도 어텐션 파라미터는 11.4B로
R1 총 671B의 **1.7%** 입니다. MoE에서 어텐션 방식은 모델 크기를 좌우하지 않습니다 — 바뀌는
것은 캐시와 대역폭입니다.

### `h`를 저장하는 것과의 차이는 차원뿐입니다

GLM-5.2 기준, 토큰당·레이어당 원소 수입니다. **[유도]**

| 무엇을 저장하나 | 원소 수 | K/V 저장 대비 |
|---|---|---|
| K·V 그대로 (헤드별) | 32,768 | 1배 |
| `h` (6144) | 6,144 | 5.3배 작음 |
| `c_KV` + 위치키 (512+64) | **576** | **56.9배 작음** |

`h`를 저장하는 것만으로도 5.3배 이득이고, 병목이 거기서 다시 10.7배를 가져옵니다. **왜 512로
충분한가**가 이 설계의 내용입니다 — `h`에는 FFN이 쓸 정보, 다음 레이어가 쓸 정보까지 들어
있지만 K/V는 그중 일부만 씁니다. `W^DKV`는 **`h`에서 K·V가 사는 부분공간**을 학습으로 찾습니다.

**대역폭이 더 실질적입니다.** 어텐션은 매 스텝 과거 전부를 읽으므로, 내적이 512차원에서
일어나느냐 6144차원에서 일어나느냐가 읽는 바이트와 곱셈 횟수를 12배 가릅니다.
[5.2장](../README.md#52-디코딩)대로 디코딩은 메모리 대역폭 병목이니 이 12배가 곧 속도입니다.

## 6. 흡수 — 결합법칙을 쓰는 것

점수는 스칼라(내적)이므로 행렬을 어느 쪽에 곱해도 결과가 같습니다. **[1차]** (Appendix C)

```
score = q_A · k_B  =  q_Aᵀ (W^UK c_B)  =  (W^UKᵀ q_A)ᵀ c_B
                                          └──────┬──────┘
                                        스텝당 딱 한 번만 계산
```

가운데 항은 "저장된 `c_B`를 `k_B`로 펴서 내적", 오른쪽 항은 "`q_A`를 미리 변환해 두고 `c_B`와
바로 내적"입니다. **결과는 완전히 같고 비용이 다릅니다** — `c_B`는 과거 토큰 10만 개고 `q_A`는
하나입니다. 행렬을 "많은 쪽"에서 "하나인 쪽"으로 옮기면 10만 번 할 일이 1번이 됩니다.

> **비유**: 달러로 적힌 과거 가격표 10만 장과 원화로 된 내 예산 하나가 있을 때, 가격표를 전부
> 원화로 환산할 필요 없이 **내 예산 하나를 달러로 바꿔** 비교하면 됩니다. `W^UK`가 그 환율이고
> 쿼리 쪽으로 옮기는 것이 흡수입니다.

**Value 쪽도 같습니다.** 출력은 `Σ (가중치 × v_B)`이고 `v_B = W^UV c_B`인데 `W^UV`는 B마다 같은
행렬이므로 밖으로 빼낼 수 있습니다 — `W^UV (Σ 가중치 × c_B)`. 뒤에 어차피 `W^O`가 곱해지므로
`W^O·W^UV`를 하나로 미리 합칩니다. 논문 표현은 *"we do not need to compute keys and values out
for each query"* 입니다.

**RoPE가 흡수를 막는 이유**도 같은 논리입니다. 두 행렬이 인접해야 미리 곱할 수 있는데,

```
score = q_Aᵀ  R(B−A)  W^UK c_B
              └──┬──┘
        B마다 다른 회전이 사이에 끼어듭니다
```

`R`이 상대 위치에 따라 달라지므로 B마다 다른 행렬이 필요해지고 이득이 사라집니다. 해법이
**위치 정보를 담은 키만 64차원 따로 떼어 회전을 적용한 상태로 저장**하고 모든 헤드가 공유하게
하는 것입니다(§2.1.3). 그래서 저장량이 512 + 64 = 576입니다.

**흡수하면 MLA는 MQA와 같은 모양이 됩니다.** **[유도]**

```
키 쪽 :  score_i = q_iᵀ (W^UK_i c)    = (W^UK_iᵀ q_i)ᵀ c
값 쪽 :  out_i   = Σ 가중치 · W^UV_i c = W^UV_i (Σ 가중치 · c)
                                            ↑ 모든 헤드가 같은 c
```

캐시에 있는 `c` 하나가 **모든 헤드의 키이면서 동시에 값**입니다. 헤드별 차이와 K/V의 차이는
데이터에서 사라지고 가중치로 옮겨갑니다. 본문 6.5의 그림을 MQA와 같은 문법으로 그린 근거이고,
[V4가 이 형태를 아키텍처로 굳힌 것](./deepseek-v4.md#23-k와-v가-같은-텐서입니다)도 같은 이유입니다.

**단서**: 흡수는 디코딩(토큰 하나)에서 확실한 이득입니다. 프리필은 처리할 토큰이 수천 개라
"하나인 쪽"이 하나가 아니어서 셈이 달라집니다. 실제 엔진이 단계마다 다른 경로를 쓰는지는
**[미확인]** 입니다.

## 7. K·V를 미리 곱해 둘 수 없는 이유 — 그리고 그걸 하는 계열

흡수는 **가중치 행렬끼리** 미리 곱하는 것입니다. 토큰별 K·V 데이터를 미리 결합하는 것은 다른
이야기이고, 소프트맥스 어텐션에서는 불가능합니다.

```
o_A = Σ_B  softmax_B( q_A · k_B ) · v_B
                └────┬────┘
        비선형 + 모든 B에 걸친 정규화가 K와 V 사이에 끼어 있습니다
```

`k_B`와 `v_B`를 묶으려면 둘이 곱셈으로 인접해야 하는데, 점수는 softmax를 통과한 뒤에야 `v_B`의
가중치가 됩니다. 게다가 softmax의 분모는 모든 B의 점수 합이라 쿼리를 알기 전에는 확정되지
않습니다.

**그런데 softmax를 버리면 그 결합이 가능해집니다.**

```
o_A = Σ_B (q_A · k_B) v_B  =  q_Aᵀ ( Σ_B k_B v_Bᵀ )
                                    └──────┬──────┘
                              A와 무관 → 미리 누적해 둘 수 있음
```

이 `Σ k vᵀ`가 **선형 어텐션의 상태(state)** 이고, [6.3장 Gated
DeltaNet](../README.md#63-qwen3-next-80b-a3b---gated-deltanet)과
[6.6장 KDA](../README.md#66-kimi-k3---kimi-delta-attention-kda)가 말하는 "요약 노트"의
정체입니다. 토큰이 늘어도 이 행렬 하나에 계속 고쳐 쓰므로 **크기가 컨텍스트 길이와 무관하게
고정**됩니다.

| | 무엇을 미리 곱하나 | 대가 |
|---|---|---|
| **흡수** (MLA) | 가중치 행렬 | 없음 — 결과가 수학적으로 동일 |
| **상태로 누적** (선형 어텐션) | 토큰별 K·V 데이터 | softmax 포기 → 정확한 회상이 약해짐 |

흡수는 **같은 답을 더 싸게** 구하는 것이라 공짜이고, K·V를 미리 결합하는 쪽은 **모델을 바꾸는**
것이라 공짜가 아닙니다. 그래서 Qwen3-Next와 Kimi K3가 선형 레이어를 3:1이나 69:24로 섞고,
정확한 회상이 필요한 몫은 풀 어텐션 레이어에 남겨 둡니다.

|---|---|

| "MLA는 계산된 K/V를 압축한다" | 압축의 입력은 **`h`**입니다. 전체 K/V를 만든 적이 없습니다 |

| "GQA는 어텐션 연산을 줄인다" | 저장과 읽기만 줄입니다. 점수 계산 횟수는 그대로입니다 |

| "MLA가 MQA보다 캐시가 작다" | **항상 2.25배 큽니다.** MQA가 최소이고, MLA는 품질로 이깁니다 |

| "MLA는 파라미터도 늘어난다" | 저랭크 분해라 **줄어듭니다**(같은 기하 MHA의 39.8%) |
